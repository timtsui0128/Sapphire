# TopLet 0.1.11 — Window placement compatibility

## English

- Window snapping waits for asynchronous size and position changes before sending the next instruction. Bounded retries and a final stability check address apps that acknowledge a resize before applying it, including the left/right half-screen case.
- A scoped Enhanced UI compatibility adjustment avoids conflicting resize animations and restores the prior state when placement ends. VoiceOver and Switch Control retain their existing mode.
- Error messages now distinguish full-screen windows, permission denial, unavailable windows, unsupported movement/resize, reported minimum sizes, and a window that did not settle. Failures are no longer all described as a layout being too small.
- Keeps the top-center activation area and the Apple Development signing identity from 0.1.10. This remains a personal test build without Apple notarization.

Validation: production placement tests with simulated asynchronous left/right halves, busy/error/ignored responses, drag cancellation, multi-display geometry and Enhanced UI restoration; English/Chinese localization audit; full app build and signature checks. Live Chrome window behavior and permission retention across the update still require validation on the user's Mac.

## 简体中文

- 分屏时等待窗口完成异步缩放、移动，再发送下一条指令；有限重试并核对最终位置，处理左右半屏等布局中应用提前返回成功、实际调整尚未完成的情况。
- 针对增强辅助功能界面的缩放动画加入临时兼容处理，分屏结束后恢复原状态；启用 VoiceOver 或切换控制时保留原模式。
- 分别提示全屏、权限、窗口已失效、不支持移动／缩放、已知最小尺寸限制和窗口未完成调整，不再把所有失败都解释成区域太小。
- 保留顶部正中的分屏触发区域，继续使用 0.1.10 的同一 Apple Development 签名身份。本版本仍是未经 Apple 公证的个人测试版。

验证包含异步左右半屏、忙碌／错误／忽略指令、取消、多显示器坐标、兼容状态恢复、中英文本地化、完整构建及签名检查。实际 Chrome 窗口表现，以及更新后的权限保留，仍需在用户的 Mac 上确认。
