# 外接屏切回内置屏时适配刘海面板和设置窗口

交付为 `output/Sapphire Click.app`，压缩包为 `output/Sapphire-Notch-Click-Recovery-arm64.zip`。先从 Sapphire 菜单选择 **Quit**，再打开新版。

在 **Settings → About** 的版本文字中可看到 **Notch Click Recovery 5**。先前的 `Sapphire Fit.app` 只修正 Sapphire 自身的设置窗口；本版补上用户照片中顶部展开刘海面板的实际越界问题。

## 顶部展开的刘海面板

照片中的天气定位权限提示让单个天气卡片的固有宽度达到 556 点，超过布局原先预估的 210 点。音乐、天气、F1、股票和日历排成一行后，会把整个面板撑到屏幕以外。天气卡片现在限定为 260 点，提示可换行截断，鼠标悬停可读取完整说明，风速／湿度等数值保留各自空间。

展开轮廓的目标尺寸现在受目标屏幕约束，左右至少留出 16 点，底部避开 Dock。内容使用保持同一视图状态的滚动视口；内容过长时可以横向或纵向滚动，而不会继续撑大外框。切回小屏后会清除旧屏幕的展开尺寸缓存，更新卡片容量与内容测量，即使两块屏幕的刘海样式配置相同也会重新布局。

原生宿主窗口和 SwiftUI 舞台一起重新适配。舞台不会保留旧显示器的高度，也不会因像素取整超过当前屏幕宽度。显示器稳定性检查包含可用区域、缩放比例和摄像头安全区域，避免只看显示器编号和矩形时过早认定切换完成。

回归检查：`bash Tools/NotchScreenFitTests/run.sh`。直接编译生产天气卡片、滚动视口、显示指标、宿主窗口和舞台几何代码，覆盖 960／1280／1512／1920／3440 点屏宽、负坐标、1／1.5／2 倍缩放、外接屏→内置屏→外接屏、长权限提示及滚动到最后一项。原生离屏渲染保存在 `output/notch-fit-renders/`。音乐、F1、股票及日历使用布局夹具，不启动实际服务；未切换物理显示器。

## Sapphire 设置窗口

此前设置窗口只在首次创建时读取可用区域，没有随着目标屏幕更新尺寸上限。本版保留上一版对该窗口的修复。

显示器拔插、窗口移动到另一块屏幕或缩放变化后，会重新选择当前连接的目标屏幕，更新窗口的最小／最大尺寸，再把设置窗口缩小、移回该屏幕的可用区域。系统菜单栏和 Dock 占用的空间不算可用区域。窗口已经完整位于屏幕内时保留其大小和位置。

屏幕切换时系统可能稍后再自动移动窗口，因此会立即适配一次，并在短暂等待后再次检查。打开或重新打开设置时也执行这些检查，以恢复 SwiftUI 首次布局可能重设的窗口尺寸上限。旧的延迟适配会失效，避免它把窗口拖回先前的显示器。设置窗口由原生窗口控制尺寸，页面内容的 SwiftUI 理想尺寸不会重新撑大外框。

显示器与缩放检查使用合成屏幕矩形和不显示的原生测试窗口；不会替用户拔插显示器或更改 macOS 的显示设置。黑色面板、蓝牙静音及锁屏暂停行为保留。

回归检查：`bash Tools/WindowFitTests/run.sh`。测试直接编译生产几何与原生窗口适配代码，覆盖断开的旧显示器、负坐标、Dock／菜单栏边界、旧最小尺寸与 SwiftUI 延迟布局后的再次适配。
